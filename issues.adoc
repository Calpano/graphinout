= Open Issues
:toc:

Issues surfaced while triaging test-log spam on 2026-06-30 (full `mvn clean test`, all
modules). After silencing the three noise sources (GmlTokenizer per-token WARN, Apache
Jena's RIOT logger, and the `ReaderTests` probe catch), the log shrank from ~890,000 to
~15,900 lines — and the warnings below stopped being drowned. Most are emitted because
detection probes every reader against every file, but several point at genuine behaviour
worth fixing. Severity is the author's estimate; "investigate" means *confirm whether it
fires on inputs that should parse, vs. detection probing incompatible files*.

== Done (noise removed)

* `GmlTokenizer` no longer logs a WARN per unhandled token; it reports a single capped
  `ContentError` and bails once the input is clearly not GML (was ~860k log lines).
* `logback-test.xml` (base) silences `org.apache.jena` — its RIOT parser logs at ERROR on
  non-RDF input; the RDF reader already surfaces real problems as `ContentError`s.
* `ReaderTests.testWithAllResource` logs expected probe failures at DEBUG, not WARN+stacktrace.
* *log-content-errors-as-ContentError sweep (read side):* readers now report parse problems
  through the `ContentError` handler instead of logging them directly. Converted to a reported
  `ContentError`: `Json2CjWriter` unknown-property (I1) and `Graphml2CjDocument` undeclared-key
  (I2). Demoted to DEBUG (already reported elsewhere): `GraphmlReader`, `Xml2GraphmlWriter`,
  `GexfReader`, `OcifDoc2CjDoc` (ocif + ocif07), `CjNormalizer`. Added the no-Throwable
  `IHandleContentErrors.sendContentError_Warn(String)` overload. Full test log is now ~3,400
  lines (was ~890,000).

== Genuine issues

=== I1 — CJ reader drops unknown properties [HIGH / investigate — now reported]
`Json2CjWriter` encounters a key that is not a known CJ property, then drops the value.
Observed keys: `options` (134×, on RootObject — likely a grale or OCIF document property), and
JSON-LD/RDF keys `@id` `@type` `@graph` `nodes` `maker` `primaryTopic` `label` `created`, plus
`foaf:*` / full-IRI keys.

* *Status:* no longer a silent WARN — it now reports a `ContentError` (Warn) so the caller can
  see the drop. (Surfaced no asserting-test failures, i.e. it fires on probe/non-CJ paths.)
* *Risk:* still **data loss** — the value is dropped, just visibly now.
* *Action:* determine which reader+fixtures produce each key; if they are real inputs (grale
  `options`, JSON-LD `@id`/`@type`), model the property rather than dropping it.

=== I2 — GraphML `<data>` referencing an undeclared `<key>` [MEDIUM — now reported + recovered]
`Graphml2CjDocument` hit `<data key='dN'>` with no matching `<key id='dN'>`.

* *Status:* now reports a `ContentError` (Warn) and recovers by auto-creating a string key (so
  no data loss). `GraphmlReaderContentErrorTest` now tolerates recoverable Warns, asserting only
  no Error-level errors.
* *Found:* the external fixture `graph-test-data/xml/graphml/yworks/yed-3.12.2/graph1_test.graphml`
  references 5 undeclared keys (`d5 d6 d7 d9 d10`), plus one more file with a single undeclared
  key — both are malformed per the GraphML spec (every `<data key>` must be declared).
* *Action:* none required (recovery is correct); optionally fix the fixtures to declare the keys.

=== I3 — Neo4j writer emits empty output for some CJ inputs [MEDIUM / investigate]
`NeoNj JSON output is empty for json/connected-json/.../custom-data-simpleN.cj.json (may not …)` ×2.

* *Action:* check whether these CJ documents should produce Neo4j output; if so the LPG
  writer is dropping them.

=== I4 — GraphmlReader logged every ContentError at WARN [DONE]
`GraphmlReader` and `Xml2GraphmlWriter` both *reported* a `ContentError` and then re-logged it
at WARN. Fixed: the redundant logs are now DEBUG; the `ContentError` handler is the single
channel.

=== I5 — OCIF: many fixtures lack a schema declaration [LOW]
OCIF reader logs `Found no OCIF schema, using v0.6` / `assuming …/ocif/vN.N.N` ~84×, defaulting
the version.

* *Action:* decide if the test data should declare a schema; otherwise drop this to INFO so a
  reasonable default isn't reported as a warning.

=== I6 — A few Jena `riot` ERROR lines still leak [LOW]
~6 `ERROR riot - …` lines (e.g. `Unrecognized keyword: A`) survive the `org.apache.jena` OFF
rule — emitted under a logger named `riot` from a module that doesn't pick up base's
`logback-test.xml`. Negative-test RDF input.

* *Action:* add `<logger name="riot" level="OFF"/>` (or give that module its own config).

== Known limitations (not bugs)

* I7 — `MermaidOutput`: `Cannot represent hyper-edge in Mermaid flowchart` ×3. Mermaid
  flowcharts have no hyper-edge syntax; the warning is expected. Documented for completeness.

== Cross-cutting note
The root cause of the original spam was an anti-pattern: **readers logging parse problems
directly instead of reporting them via the `ContentError` handler.** The read-side sweep is
done (see the Done section). Still **open: the output writers** — `DDotOutput`, `CjDocument2D2`,
`GmlOutput` (hyper-edge + "skip node without id"), `MermaidOutput`, `TgfOutput`,
`TripleTextOutput` log `Cannot represent …` on write-time data loss. They have no error channel
(don't extend `BaseOutput`); giving writers a `ContentError` sink is a separate, larger change.
