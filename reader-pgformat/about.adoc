= PG-JSON Reader/Writer

== Overview

The PG-JSON Reader/Writer module provides support for reading and writing graph data in the PG-JSON (Property Graph JSON) format.

== Supported Format

This reader/writer supports the PG-JSON format as specified at:
https://pg-format.github.io/specification/

=== File Extensions

* `.pg.json`
* `.pgjson`

=== Format Specification

PG-JSON is a JSON-based format for representing property graphs. A PG-JSON document is a JSON object with two mandatory fields:

==== Document Structure

[source,json]
----
{
  "nodes": [ /* array of node objects */ ],
  "edges": [ /* array of edge objects */ ]
}
----

==== Node Format

[source,json]
----
{
  "id": "101",
  "labels": ["person"],
  "properties": {
    "name": ["Alice"],
    "country": ["United States"]
  }
}
----

Node fields:
* `id`: Mandatory, unique string identifier
* `labels`: Mandatory, array of unique non-empty strings
* `properties`: Mandatory, object mapping keys to arrays of scalar values

==== Edge Format

[source,json]
----
{
  "id": "e1",
  "from": "101",
  "to": "102",
  "undirected": false,
  "labels": ["likes"],
  "properties": {
    "since": [2015],
    "engaged": [false]
  }
}
----

Edge fields:
* `id`: Optional, unique string identifier (can be null)
* `from`: Mandatory, source node identifier
* `to`: Mandatory, target node identifier
* `undirected`: Optional, boolean indicating if edge is undirected (defaults to false)
* `labels`: Mandatory, array of unique non-empty strings
* `properties`: Mandatory, object mapping keys to arrays of scalar values

== Usage

=== Reading PG-JSON

[source,java]
----
PgJsonReader reader = new PgJsonReader();
File inputFile = new File("graph.pg.json");
SingleInputSourceOfFile inputSource = new SingleInputSourceOfFile(inputFile);
ICjDocument document = reader.readToCjDocument(inputSource);
----

=== Writing PG-JSON

[source,java]
----
PgJsonReader writer = new PgJsonReader();
InMemoryOutputSink sink = InMemoryOutputSink.create();

ICjStream stream = writer.createCjStream(sink);
// Write your graph data to the stream
// ...

String pgJson = sink.getBufferAsUtf8String();
----

== Mapping to CJ

The format id is `pg-json`; the engine finds the reader and writer via `PgJsonService`.

.Reading PG-JSON
* Node and edge `labels` become CJ label entries, all of them, in order.
* A property with one value becomes a scalar CJ data property; a property with several values becomes a JSON array.
  Numbers keep their full range and precision (`long`, `BigInteger`, `double`).
* An edge `from -> to` becomes a CJ edge with `from` as source (endpoint direction `in`) and `to` as target
  (direction `out`). CJ direction is seen from the edge. `"undirected": true` gives two undirected endpoints.
* `nodes` and `edges` may come in either order.

.Lenient reading, reported as content errors
* A scalar property value instead of an array is read as one value (warning).
* A numeric `id`, `from` or `to` is read as its text (warning).
* `null`, nested objects and nested arrays inside a value array are skipped; the other values and properties are kept.
* A node without `id` is read without one (error); an edge without `from` or `to` is skipped (error).
* Duplicate node ids and edges that reference unknown nodes are reported (warning).
* Malformed JSON fails with an `IOException` that names line and column.

.Writing PG-JSON
* CJ labels become `labels`. An element without labels gets an empty array; no label is invented.
* An object-valued CJ data property becomes a property: arrays of scalars become multiple values, a scalar becomes a
  one-element array. Nested objects or arrays are written as a JSON string (warning).
* Nodes without an id get a generated id (`node_0`, `node_1`, …) that does not collide with existing ids.

== Limitations

PG-JSON is one flat property graph whose edges connect exactly two nodes. Writing reports what it cannot represent
to the content error handler:

* Nested graphs and multiple CJ graphs are merged into one graph (warning).
* An edge with more than two endpoints is written from its first source to its first target (warning); an edge with
  fewer than two endpoints is not written (error).
* CJ data that is not a JSON object (e.g. a plain string) has no place in PG properties and is not written (warning).
* Label languages are dropped: a multilingual CJ label becomes several PG labels.
* CJ treats labels and data keys as unordered, so a round trip may reorder them.
