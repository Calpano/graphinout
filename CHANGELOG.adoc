= Changelog
:toc:

All notable changes to GraphInOut, newest first. Format based on
https://keepachangelog.com[Keep a Changelog]. Releases are tagged
`graphinout-<version>`; library modules publish to Maven Central and the `gio` CLI
ships via GitHub Releases. Curated from git history — routine merges, dependency
bumps and "minor/doc/WIP" commits are omitted.

== Unreleased

Added::
* `GraphmlValidator.validate(InputSource)` returns the GraphML 1.1 XSD findings with line and column, not just a
  boolean. Tests now check that GraphML written from CJ is schema-valid, and that schema-valid GraphML input stays
  valid after a round trip. Known gaps: CJ ids that are URIs are written as GraphML ids, which must be NMTOKENs,
  and endpoint data is written as a `cjData` attribute the XSD does not allow.
* `SingleInputSource.readContentAsUtf8String()`: reads the whole input as UTF-8, closes the stream, and throws
  `IOException`. `getContentAsUtf8String()` now delegates to it and wraps failures in `UncheckedIOException`.
* `devtools` tool `ThirdPartyLicenses` regenerates the dependency table in `THIRD_PARTY.adoc` and the license
  texts under `LICENSES/` from `mvn license:aggregate-add-third-party`; `how-to-release.adoc` runs it as Step 0b.
* PG-JSON (`pg-json`, `.pg.json`, `.pgjson`) is registered with the engine and the CLI (`PgJsonService`) and
  detected by file name and by content (array-valued `properties`, `labels` arrays, `undirected`).

Changed::
* Module POMs declare what each module actually uses, checked with `mvn dependency:analyze` and against the
  sources. Modules now declare `foundation-pure`, `base-api` and `slf4j-api` directly instead of getting them
  through `base`; unused entries are gone (mostly `mockito-junit-jupiter` and test-jars nobody used); `testdata`
  is test scope everywhere, so it no longer ships with `reader-cj`, `reader-neo4j`, `reader-pgformat`,
  `reader-grale` and `engine`.
* `foundation-emulation` (the J2CL stand-ins for the jspecify and Jackson annotations) is no longer on JVM
  classpaths, where it shadowed the real annotations. The root POM excludes it from `foundation-pure`.
* Truth is no longer added to every module from the root POM, and it now brings Guava (as `-jre`, via the managed
  version) in test scope. Before, Truth users only compiled because `testdata` and `base` exported Guava.
* `THIRD_PARTY.adoc` and `LICENSES/` regenerated: versions match the build again (e.g. JUnit 6.1.3, Jena 6.2.0,
  logback 1.6.7), 11 libraries that are no longer used are gone, and `ddotit-core` and Jackson 3 are listed.

Fixed::
* The CJ, CJ-GEF, D2, DDot, Mermaid, OCIF, Pajek, PlantUML, Structurizr DSL, adjacency-list, edge-list and TGF
  readers now close the input stream they read; before, each read leaked one stream.
* Every jar (main, `-sources`, `-tests`, `-javadoc`, and the `cli` uber-jar) now ships GraphInOut's
  BSD-3-Clause license as `META-INF/LICENSE`, as clause 2 requires for binary redistributions. Before, no
  jar contained it; the `cli` uber-jar's `META-INF/LICENSE` came from whichever dependency shade saw first.
* PG-JSON reader: directed edges were read backwards (`from` became the CJ target); integers beyond 32 bits threw;
  edges kept only their first label and properties only their first value (now a JSON array); a scalar or nested
  property value made the parser skip the following properties; `edges` before `nodes` threw; a `null` id became
  the id `"null"`. Spec violations are now read leniently where possible and reported with line and column.
* PG-JSON writer: CJ arrays become multiple property values instead of a JSON string; no `Node`/`Edge` label is
  invented for unlabeled elements; generated node ids no longer collide with existing ones; edges with fewer than
  two endpoints are no longer written without `from`/`to`. Merged graphs, hyperedges and non-object data are
  reported to the content error handler.
* Neo4j APOC JSON reader: relationships were read backwards (`start` became the CJ target). `start` is now the source
  (direction `in`), `end` the target (`out`), matching the writer and the other readers.
* GraphML reader: an edge or hyperedge endpoint that references an undeclared node is reported again as an Error
  with line and column (`Edge 'e1' references a non-existent node ID: 'n4'`). GraphML ids are document-wide, so the
  check runs at `</graphml>`.
* `ValidatingCjStream` and `ValidatingCjWriter` check endpoint references against one document-wide id space, as CJ
  specifies: an edge may reference a node in a nested or outer graph, or (edges on edges) another edge. Before, every
  nested graph reset the known ids, and `ValidatingCjWriter` (used by `GioReader.isValid`) rejected such documents.
* The generic reader test (`AbstractReaderTest`) could not fail: it swallowed every exception and mismatch, and it
  located files with `ClassLoader.getSystemResource`, which misses resources inside jars. It now reports every
  failing file with its root cause; expected errors are compared at Error level, warnings are logged.
* Thread safety: the HTML entity table shared by the GraphML and GEXF readers was initialized lazily without
  synchronization and marked ready before it was filled. Readers on other threads could see a missing or half-built
  table, so an entity like `&Eacute;` stayed undecoded, the XML parse failed and the read returned no document. The
  table is now built once at class initialization and immutable. `foundation-pure`'s `LoggerFactory` (a `HashMap`
  filled from any thread) is synchronized. New tests read concurrently on 8 and 16 threads.

Removed::
* `GraphmlReader` no longer validates input against the GraphML XSD (#115). Only 13 of 84 GraphML files in the test
  corpus are schema-valid (yEd elements in `<data>`, ad-hoc attributes), the findings only went to the log, and the
  pass cost an extra parse plus a classpath scan. It also parsed without the HTML entity decoding `read()` uses, so
  `isValid()` threw a `RuntimeException` on GraphML with entities like `&eacute;`. `isValid()` is now the default
  (the input reads without errors or warnings), so such a file is reported as not valid, given the warning
  `read()` issues for the auto-fixed entity, instead of throwing. Removed `GraphmlReader.getSchema`, `SchemaCache`, the unused yEd
  schema copies, and the runtime dependency on ClassGraph.
* The direct `commons-io` dependency. All our uses were replaced with JDK IO, and a `maven-enforcer-plugin` rule
  stops modules from declaring it again. It still comes in transitively with Jena (`reader-rdf`), which needs it.
* Unused dependencies: JGraphT (`jgrapht-core`, `jgrapht-io`) and `commons-text` from `reader-jgrapht`, which reads
  graph6, sparse6 and digraph6 itself; joni and Guava from `base`; Guava from `testdata`; joni from the root
  dependency management.

== 0.2.4 — 2026-11-19

Added::
* `gio detect <input>` probes every reader and ranks format candidates by file name, content kind, vocabulary
  and parse quality; prints one JSON line with the best format, a confidence tier (`CONFIDENT` / `AMBIGUOUS` /
  `UNKNOWN`) and per-reader signals, stats and errors.
* Developer guides: `doc/usage.adoc` (using GraphInOut as a library), `doc/writing-a-converter.adoc` (adding a
  format), an up-to-date `doc/architecture.adoc`. Their code examples are tests.
* `reader-gxl` reads and writes GXL 1.0 (Graph eXchange Language): nested graphs in nodes and edges, hyperedges
  (`<rel>`), node and edge types, typed attribute values, mixed edge directions (`defaultdirected`). It never fetches
  the DTD GXL files reference and resolves no external entities. All 393 GXL files in graph-test-data round-trip
  GXL → CJ → GXL → CJ unchanged, apart from graph ids that GXL requires and the writer generates where missing; the reader also accepts the `source`/`target` edge attributes and the stray
  whitespace before `<?xml` found there. Format detection recognises GXL.
* Remote content policy: `OFFLINE` (no network), `PUBLIC_WEB` (default) or `CUSTOM` (own fetcher), per reader
  (`RdfReader.setRemoteContentPolicy`), JVM-wide (`RemoteContentPolicy.setDefault`, system property
  `graphinout.remoteContent`) or per CLI run (`gio --offline`). Popular JSON-LD contexts (schema.org, W3C
  credentials, ActivityStreams, DID, security) are bundled as hash-pinned snapshots and work offline; servers can
  pre-warm more (`JsonLdContexts.prewarm`, list in `doc/popular-vocabularies.adoc`). Every remote context used is
  reported as an info message and in the CJ document data (`jsonld:remoteContext`).
* `gio`: when format detection fails for a file whose name matches a format, the reader's error is shown.
* `reader-dot` resolves ports the way Graphviz does. Ports declared by `record`/`Mrecord` labels and
  HTML `PORT` attributes become CJ node ports; compass points (`A:n`, `A:p:e`) are built-in ports; the
  `tailport`/`headport` edge attributes and `edge [...]` defaults set endpoint ports. A port that is
  neither declared nor a compass point is reported as a warning with its location, as Graphviz does,
  and kept in endpoint data so DOT output writes it back.
* The DOT writer makes CJ node ports mean something to Graphviz: `shape=record` and, if needed, a record
  label with one field per port. HTML labels are written as `<...>` again, not as quoted strings.

Changed::
* `reader-ocif` implements OCIF v0.7 (it still reads v0.6 files). The former `reader-ocif07` module is now
  `reader-ocif` (Maven artifact and Java package `com.graphinout.reader.ocif`); the v0.6 implementation is gone.
  CJ round trips keep multiple graphs, nested graphs, graph data and edge labels.
* `engine` depends on `reader-example` in test scope only, so its placeholder `example` format is no longer
  registered (it ranked high in format detection).

Security::
* Vulnerabilities can be reported privately via GitHub; see `SECURITY.md` (supported versions, scope, response time).
* `reader-graphml` no longer resolves XML external entities (XXE) during GraphML validation. Format
  detection (`GraphmlReader.isValid`, used by the engine and the CLI to pick a reader) and
  `GraphmlValidator` parsed input with an unhardened parser, so a crafted file could make them open local
  files or URLs. `XmlFactory` now offers one hardened parser factory that fails rather than run unhardened.
  Compiling the bundled GraphML schemas may not access external files or URLs either.
* No reader opens local files, fetches URLs or reads environment variables because an input says so:
** `reader-rdf`: JSON-LD remote `@context` URLs are loaded only through a new safe-fetching layer (`base`
   package `com.graphinout.base.fetch`, new module `base-http`): `http(s)` only, ports 80/443, connections only to
   public internet addresses (checked on the resolved address, pinned against DNS rebinding), every redirect and
   `Link rel="alternate"` hop checked again, size/time/count budgets per input, gzip bombs capped. Before, Jena loaded
   any context URL, including local files. See `doc/url-fetching-safe.adoc`.
** `reader-structurizr-dsl`: `!include`, `workspace extends`, `!docs`, `!adrs`, `!script`, `!plugin` and
   `${NAME}` environment variables are disabled; such input is reported as an error. Before, local files were
   included and environment variables substituted.
** `reader-plantuml`: PlantUML runs in its `SANDBOX` security profile, so `!include`, `!includesub`, `!import`,
   `%load_json` and `%file_exists` no longer touch the file system.

Fixed::
* `reader-rdf` registered N-Quads, TriG and TriX twice, so the engine listed them twice.
* `reader-graphml` keeps GraphML 1.1 time-stamped data (`<data key="k" time="1">`). In CJ, such a
  property is a time series `[{"time": 1, "value": …}, …]`, written back as one typed `<data time="…">`
  each; before, the times were lost and the values merged into an untyped array
  (https://github.com/Calpano/graphinout/issues/158[#158]).
* `reader-graphml`: when a `<key>` must change type on writing, it keeps its id, `<desc>`, `<default>`
  and extra attributes such as `dynamic="true"`, instead of being replaced by a generated key
  (https://github.com/Calpano/graphinout/issues/157[#157]).
* `reader-dot`: a quoted attribute value starting with `<` (such as the record label `"<f0> a|<f1> b"`)
  is a plain string, not an HTML label.
* `reader-cj-gef` read GEF `source`/`target` (and `sources`/`targets`) with reversed endpoint
  directions, so every such edge came out backwards. Now `source` → `in`, `target` → `out`, as the
  GEF spec defines (https://github.com/Calpano/graphinout/issues/156[#156]).

* Tests on JUnit 6.1.3, Mockito 5.24.0, Truth 1.4.5, surefire 3.6.1; build plugins updated.
* Then: Jackson 3.3.0, Guava 33.8.0, logback 1.6.7, slf4j 2.0.20, commons-lang3 3.22.0,
  json-schema-validator 3.0.9, joni 2.2.10, PlantUML 1.2026.10, error_prone_annotations 2.53.0;
  flatten-maven-plugin 1.9.0, and every module on maven-jar-plugin 3.5.1 (five still pinned 3.0.2).
* `reader-jgef` renamed to `reader-cj-gef` (package `com.graphinout.reader.cjgef`, classes
  `CjGefReader`/`CjGefService`): it reads Connected JSON's Graph Entry Format, not a separate format.
  Format id `json-gef` and file extensions are unchanged.
* `reader-cj-gef` warns for every unknown key it moves into `data`, with its path in the input
  (`nodes[1].foo moved to data`), and for one it must drop because `data` is not an object.
* `CjDocuments.parseCjJsonString(name, content, contentErrorHandler)` reports content problems;
  unknown-key warnings now name the path (`graphs[0].nodes[3].foo`).
* JSON read failures name the line, column and exception type.

Fixed::
* The CJ reader skips an unknown key's whole value. An object or array value, or a later `data`
  (as in `reader-rdf`'s example with a graph-level `baseUri`), failed with `EmptyStackException`.

== 0.2.2 — 2026-11-01

Added::
* `base-api` — one dependency for consumers that only need graphinout's core APIs
  (the JSON document types and query interfaces) without the readers.
* `SelfCheck` utility listing the formats every `GioReader` and `GioWriter` supports.
* GXL DTD bundled with `reader-gxl`; `PgJsonReader` warns about unknown fields.

Changed::
* `reader-ddot` parses with `it.ddot:ddotit-core` 0.3.1 (Maven Central) instead of its own grammar,
  and writes only forms the conformant reader can read back (round-trip over the canonical corpus:
  34 of 35, up from 30; the one left is benign).
* `reader-ddot`: per-link metadata is stored flat in CJ edge data. `,, ..since.. 2025 ;; a note`
  becomes `{"since": "2025", "text": "a note"}`, no longer
  `{"ddot-it:props": {"since": "2025"}, "ddot-it:text": "a note"}`.
* `reader-dot` scans HTML strings the way Graphviz does (depth-counting `<` and `>`) and
  rejects edge chains that continue after an attribute list, with Graphviz's line:col.
* `reader-rdf`: the Turtle reader no longer claims `.n3`.
* JSON query APIs refactored; TripleText annotations removed.
* Jackson 3.2.4, logback and Structurizr upgraded; builds on JDK 25 and 26.

Fixed::
* `reader-neo4j` reads files that interleave nodes and relationships.
* Repeated RDF statement annotations keep every value (`,, ..author.. Ann ;; ..author.. Bob`
  lost one author on the way back from RDF).
* Several invalid-fixture and round-trip tests no longer pass by returning early or swallowing failures.

== 0.2.1 — 2026-07-06

Added::
* Identity-based, ranked-confidence format detection with a `gio detect` command;
  ranking now weighs extension, content kind, vocabulary/signatures and graph
  plausibility rather than recovered graph size.
* `gio meta` — type-schema inference (node/edge types as counted nodes, `uses`
  links, `has subtype` generalisation) — plus a `convert --meta` flag.
* `reader-jgef` — JSON Graph Entry Format (GEF) reader.
* `self-loops` and `parallel-edges` to the `CjFeature` vocabulary.
* `LICENSES/` folder reproducing every (transitive) dependency's own license text,
  linked from `THIRD_PARTY.adoc`; `archive-concept.adoc` design note.
* A write-time `ContentError` channel for output writers (`GioWriter.setContentErrorHandler`):
  the format writers (GML, DOT, D2, Mermaid, TGF) now report graph data the target format cannot
  represent (hyper-edges, nodes without ids); the CLI `convert` surfaces it on stderr.

Changed::
* `AnonymizingCjStream` and the meta-graph collector are now streaming (only id/key
  maps or a type projection are buffered, not the whole document).
* GraphML/GEXF readers stream-decode HTML named entities, and GraphML parses
  non-standard `attr.type`/`edgedefault` leniently (warn instead of fail).
* Harmonized transitive dependency versions to a single resolved version each.
* Readers report parse problems through the `ContentError` handler instead of logging them
  directly, and cap the reports once an input clearly isn't their format (GML, GraphML, GEXF,
  OCIF, CJ, RDF) — removing incidental log noise during format detection.
* OCIF assumes **v0.7** (was v0.6) when a document declares no schema.
* Published POMs are flattened for Maven Central (self-contained: resolved dependency versions
  plus project metadata) via `flatten-maven-plugin`.

Removed::
* The whole-document anonymizer (the streaming one replaces it, verified equivalent
  across the test corpus).

Fixed::
* `CjWriter2CjStream`: graph-level `data` field dropped when it appears after `nodes` in the JSON;
  nested subgraph structures lost in stream output.
* `CjValidator`: false-positive "no nodes or edges" warning for graphs that contain only nested subgraphs.
* The Neo4j writer reports a `ContentError` when a document has no nodes or edges to export,
  instead of silently producing empty output.
