= Neo4j Reader

== Overview

The Neo4j Reader module provides support for reading graph data exported from Neo4j databases using the APOC JSON export procedures.

== Supported Format

This reader supports the Neo4j APOC JSON export format as documented at:
https://neo4j.com/docs/apoc/current/export/json/

=== File Extensions

* `.neo4j.json`
* `.neo4j-export.json`

=== Format Specification

The Neo4j APOC JSON export format uses JSON Lines (one JSON object per line) with two main object types:

==== Node Format

[source,json]
----
{
  "type": "node",
  "id": "0",
  "labels": ["User"],
  "properties": {
    "name": "Adam",
    "age": 42
  }
}
----

==== Relationship Format

[source,json]
----
{
  "id": "0",
  "type": "relationship",
  "label": "KNOWS",
  "properties": {"since": 1993},
  "start": {"id": "0", "labels": ["User"]},
  "end": {"id": "1", "labels": ["User"]}
}
----

== Usage

=== Programmatic Usage

[source,java]
----
Neo4jReader reader = new Neo4jReader();
File inputFile = new File("export.neo4j.json");
SingleInputSourceOfFile inputSource = new SingleInputSourceOfFile(inputFile);
ICjDocument document = reader.readToCjDocument(inputSource);
----

== Implementation Details

The reader:

* Parses JSON Lines format (one JSON object per line)
* Converts Neo4j nodes to CJ nodes with labels
* Converts Neo4j relationships to CJ edges
* Maps Neo4j node IDs to CJ node IDs
* Maps Neo4j relationship labels to CJ edge labels
* Preserves all properties on nodes and relationships
* Accepts `node` and `relationship` objects in any order. `apoc.export.json.query` emits them interleaved,
  row by row, whereas CJ requires all nodes of a graph before its edges — so relationships are buffered
  and streamed out after the last node (memory is O(number of relationships)).

The writer:

* Emits every node before any relationship, as a Neo4j import expects: `apoc.import.json` resolves a
  relationship's `start`/`end` against nodes it has already created
* Flattens the CJ graph hierarchy, see <<Limitations>>

== Neo4j Export Procedures

To export data from Neo4j in the supported format, use APOC procedures:

[source,cypher]
----
// Export entire database
CALL apoc.export.json.all("export.json", {})

// Export specific nodes and relationships
MATCH (n:User)-[r:KNOWS]->(m:User)
CALL apoc.export.json.data([n, m], [r], "export.json", {})

// Export query results
CALL apoc.export.json.query(
  "MATCH (n:User)-[r:KNOWS]->(m:User) RETURN n, r, m",
  "export.json",
  {}
)
----

== Limitations

* Currently supports JSON Lines format only (not array or nested JSON formats)
* Requires APOC plugin to be installed in Neo4j for export functionality
* A Neo4j property graph is one flat set of nodes and relationships. It has no notion of a subgraph, of a
  graph nested under a node (compound node), or of several graphs in one document. Writing such a CJ
  document therefore flattens everything into a single set: node and edge data survive, but graph-level
  identity (graph `id`, `label`, graph data) and the nesting are lost. The writer reports that loss as a
  warning-level `ContentError`; reading the result back yields one flat graph.
* A document with no nodes and no edges (e.g. only document-level data) produces no output at all; this
  too is reported as a `ContentError` rather than written as silence.
