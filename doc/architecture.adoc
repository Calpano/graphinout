== Basic Idea

.Basic Reader Idea
[plantuml,basic-idea,svg]
....

hide circle
' left to right direction

class Input {
    InputStream
    Reader
    String
}
class FileFormat {
    id
    extensions
}
class IntermediateModel as "Intermediate\nModel"
class Output {
    String
}
interface Reader
Input -> Reader
Reader *-- FileFormat: one reader\n can read\n one file format
Reader -> IntermediateModel: interprets it\nas intermediate model
IntermediateModel -> Writer
Writer <|-- GraphML
Writer <|-- ConnectedJson
Writer -> Output
....

The intermediate model is *Connected JSON (CJ)*, specified at https://j-s-o-n.org.
Every conversion is *format X → CJ → format Y*.
Earlier versions used GraphML as the intermediate model.

[[modules]]
== Modules

.Module Layers, Bottom to Top
`foundation-pure`, `foundation-shared`, `foundation-jvm`, `foundation-emulation`:: Dependency-free base layer: JSON, XML and text helpers, `ContentError`. See link:../foundation-pure/README.adoc[foundation-pure/README].
`base-api`:: The CJ model (`ICjDocument`, `ICjStream`, chunk types) and the format API types `GioFileFormat` and `InputSource`.
`base`:: The reader/writer contracts `GioReader`, `GioWriter` and `GioService`, format detection (`GioInputAnalyzer`), `OutputSink`, and CJ stream/document/JSON adapters.
`reader-__xyz__`:: One module per format family. Each contains a `GioService` with the format's reader and, where available, its writer.
`engine`:: Depends on all `reader-__xyz__` modules. `GioEngineCore` loads every `GioService` via `java.util.ServiceLoader`.
`cli`:: Command-line tool on top of the engine. Not published to Maven Central.
`testdata`:: Shared test files and loaders, used as a test dependency. See link:../testdata/README.adoc[testdata/README].
`devtools`:: Internal build and repository tools. Not published.

[[flow]]
== Data Flow

.Conversion Pipeline
[plantuml,data-flow,svg]
....
hide empty members
hide circle
left to right direction

class InputSource
class GioReader
class ICjStream as "ICjStream\n(CJ events)"
class GioWriter
class OutputSink

InputSource --> GioReader : read()
GioReader --> ICjStream : documentStart, graphStart,\nnode, edge, ...
GioWriter --> ICjStream : createCjStream()
ICjStream --> OutputSink : writes format Y
....

A reader never sees a writer and vice versa: they meet only at the `ICjStream`.
`GioReader.readToCjDocument` and `GioWriter.writeCjDocument` put a full in-memory `ICjDocument` in between instead.
Problems in the data travel separately, as `ContentError` objects sent to a handler set on the reader or writer.
