[[purpose]]
== Purpose

JSON-LD documents name their vocabularies by context URL, for example `"@context": "https://schema.org/"`.
This page lists widely used JSON-LD context URLs, grouped by community.
All of them were checked to return a JSON-LD context (November 2026).

Use the list to pre-warm GraphInOut's cache (<<prewarm>>), so that a server can then run without any network access.
How GraphInOut loads remote contexts, and why it is safe, is described in xref:url-fetching-safe.adoc#purpose[Fetching URLs Safely].

Contexts marked *bundled* ship with GraphInOut and work without network access and without pre-warming.

[[prewarm]]
== Pre-Warming the Cache

By default (`PUBLIC_WEB`), GraphInOut fetches a context when an input first names it, from public internet addresses only.
On a server, it is better to fetch the expected contexts once at startup and then refuse all network access:

[source,java]
----
Map<URI, String> failures = JsonLdContexts.prewarm(urls); // <1>
failures.forEach((url, reason) -> log.warn("Not pre-warmed: {}: {}", url, reason));
RemoteContentPolicy.setDefault(RemoteContentPolicy.OFFLINE); // <2>
----
<1> `urls`: the context URLs from the lists below, or your own selection.
Each URL is fetched with the same checks as during reading, and held for the life of the process.
<2> From now on, inputs can only use bundled, pre-warmed or already cached contexts.

`JsonLdContexts.prewarm(urls, fetcher)` uses your own `UrlFetcher` instead, for example one that goes through a corporate proxy.

The `gio` CLI is a short-lived process, so pre-warming does not apply there: it uses the bundled contexts and fetches others as needed, or runs with `--offline`.
