= Plan: New Readers (Mermaid, D2, DDot)
:toc: left
:icons: font
:source-highlighter: rouge

== Scope

Create three new Maven modules under the `graphinout` parent, each modeled on the existing
`reader-tgf` (simple, one-file format) and `reader-dot` (multi-file, with intermediate parser
class) templates:

. `reader-mermaid` — Mermaid (subset: flowchart, classDiagram, stateDiagram, erDiagram, C4, mindmap, sankey-beta, architecture-beta)
. `reader-d2` — Terrastruct D2
. `reader-ddot` — DDot.it simple triple text (`S..P..O`)

== Template Anatomy (reused by all three)

Both `reader-tgf` and `reader-dot` share this Java package and file shape, which we will replicate.

[cols="1,3"]
|===
| File | Role

| `pom.xml`
| Inherits from parent `graphinout`. Depends on `base`, `jspecify`, test-scope `testdata`, `base-tests`, `junit-jupiter`, optionally `mockito`, `truth`, `classgraph`.

| `src/main/resources/META-INF/services/com.graphinout.base.gio.GioService`
| Single line naming the `XxxService` class (Java ServiceLoader registration).

| `XxxService` (`com.graphinout.reader.<id>`)
| Implements `GioService`; `id()` returns `reader-<id>`; `readers()` returns `List.of(new XxxReader())`; `writers()` returns `List.of(new XxxWriter())`.

| `XxxReader implements GioReader`
| Declares `FORMAT_ID` + `GioFileFormat FORMAT`. `read(InputSource, ICjStream)` parses the text and emits `documentStart` / `graphStart` / `node(...)` / `edge(...)` / `graphEnd` / `documentEnd`. Forwards content issues to a `Consumer<ContentError>` (set via `setContentErrorHandler`). Optional static helper `parseXxxToCjDocument(SingleInputSource)`.

| `XxxWriter implements GioWriter`
| `createCjStream(OutputSink)` returns a `CjStream2CjWriter` over a `CjWriter2CjDocumentWriter` whose callback invokes `writeCjDocument`. `writeCjDocument` delegates to an `XxxOutput(cjDoc).toXxx()` and writes to the sink.

| `XxxDoc` (POJO model)
| Plain Java classes (`XxxNode`, `XxxEdge`, optional `XxxSubgraph`, etc.) plus a `toXxx()` serializer.

| `XxxOutput`
| Maps `ICjDocument` → `XxxDoc`. Handles labels (`firstLabelOrDesc`), URI/context expansion (`CjUris.expandId`), and direction normalization (`CjDirection.IN` / `OUT`).

| Tests under `src/test/java/com/graphinout/reader/<id>/`
| `XxxReaderTest` (unit, with `@Mock ICjStream` + interaction verification), `XxxRoundtripTest` (parameterized over `TestFileProvider.cjResourcesCanonical()` for CJ→format→CJ; and over `*.xxx` resources from `TestFileProvider.getAllTestResources()` for format→CJ→format).

| Test resources under `src/test/resources/text/<id>/`
| Hand-written `*.xxx` examples + meta files; later expand with generated fixtures.
|===

NOTE: For the simple cases (`reader-mermaid`, `reader-ddot`) we follow the *tgf shape*:
`Reader` does parsing inline, model is light (`XxxDoc.XxxNode` / `XxxDoc.XxxEdge`).
For the more complex `reader-d2` we follow the *dot shape*: a dedicated
`D2Lines2CjDocument` parser class + `CjDocument2D2` emitter.

== 1. `reader-mermaid`

=== Package & artifact
* artifactId: `reader-mermaid`
* package: `com.graphinout.reader.mermaid`
* `FORMAT_ID = "mermaid"`, extensions: `.mmd`, `.mermaid`

=== Mermaid subset to support

[cols="1,2,3"]
|===
| Diagram | Header tokens (case-insensitive) | Mapping to CJ

| Flowchart
| `flowchart [LR|TD|RL|BT]` or `graph [LR|TD|...]`
| Nodes from `id[Label]` / `id(Label)` / `id{Label}` / `id((Label))`. Edges from `A --> B`, `A -- text --> B`, `A --- B`, `A -.-> B` (dotted), `A ==> B` (thick). Directed by default (digraph). `subgraph name ... end` → CJ subgraph/group.

| classDiagram
| `classDiagram`
| `class Foo { +int x; +foo() }` → node + data props. Relations `Foo <|-- Bar`, `Foo *-- Bar`, `Foo o-- Bar`, `Foo --> Bar` → edges with a `relation` property.

| stateDiagram(-v2)
| `stateDiagram` / `stateDiagram-v2`
| `[*]` is the start/end pseudo-node. `S1 --> S2 : event` → edge with label `event`. Composite states → nested graph.

| erDiagram
| `erDiagram`
| `CUSTOMER ||--o{ ORDER : places` → two nodes + edge with cardinality + label. Attribute blocks `ENT { type name PK }` → node data.

| C4 (`C4Context`, `C4Container`, `C4Component`, `C4Dynamic`)
| `C4Context` / `C4Container` / `C4Component` / `C4Dynamic`
| `Person(alias, "label", "descr")`, `System`, `Container`, `Component` → typed nodes. `Rel(a,b,"label","tech")` → edge with `tech` data prop. `Boundary(...) { ... }` → subgraph.

| mindmap
| `mindmap`
| Indentation-based tree. Each line becomes a node; edge from parent to child. Shapes `((..))`, `(())`, `[[..]]`, `))..((` recorded as a `shape` data prop.

| sankey(-beta)
| `sankey-beta` or `sankey`
| CSV-like lines `source,target,value` → two nodes + a weighted edge (`value` as data prop).

| architecture(-beta)
| `architecture-beta`
| `group g(cloud)[Label]`, `service s(server)[Label] in g`, `s1:R -- L:s2` → nodes with `icon` data, edges with port info, groups as subgraph.
|===

<1> Service registration mirrors `TgfService`.
<2> Detects the diagram type from the first non-blank, non-comment line, then dispatches to the matching parser. Strips `%%` line comments and `%%{init: ... }%%` config blocks (recorded as document-level data).
<3> Standard writer: collects to `CjDocument` then emits flowchart-style Mermaid (the most general). Other diagram types are out of scope for writing; document this as a TODO.
<4> Maps `ICjDocument` → `MermaidDoc` (flowchart only).
<5> POJO model with `MermaidNode`, `MermaidEdge`, `MermaidSubgraph`, plus `DiagramType` enum and `direction`.
<6> Enum for the supported diagram type detection.
<7> One parser per supported diagram type, each producing a stream of CJ events into the `ICjStream`.

=== Decisions / Open questions
* Writer scope: emit **flowchart** only (the lowest common denominator). Other diagram types are read-only in v1.
* The Mermaid grammar tolerates a lot of free-form syntax. But we must really eat it all. So maybe ANTLR is required.
* Direction (`LR`, `TD`, …) is stored in document data so we can preserve it on roundtrip.

== 2. `reader-d2`

=== Package & artifact
* artifactId: `reader-d2`
* package: `com.graphinout.reader.d2`
* `FORMAT_ID = "d2"`, extensions: `.d2`

=== D2 features to support (v1)

[cols="1,2"]
|===
| Feature | Notes

| Shape declarations
| `foo`, `foo: Label`, `foo.shape: cylinder`. Becomes node `foo` with optional label + `shape` data prop.

| Containers
| `cloud: { server1; server2 }` or `cloud.server1`. Dotted paths denote nesting → subgraph.

| Connections
| `a -> b`, `a -> b: label`, `a <-> b`, `a -- b` (undirected), chained `a -> b -> c`. Map to one or two `ICjEdgeChunk`s.

| Attributes
| `foo.style.fill: red`, `(a -> b)[0].style.stroke: blue` → stored as flat data props on the node/edge.

| Comments
| `# ...` line comments, `"""..."""` block comments — stripped.

| Imports
| `@filename` — out of scope for v1; emit a `ContentError.Warn` if encountered.

| Globs / matchers
| Out of scope for v1.
|===

<1> Mirrors `DotLines2CjDocument`: tokenizer + brace-scope stack producing CJ events.
<2> Mirrors `CjDocument2Dot`: walks `ICjDocument` and emits D2 text.
<3> A trimmed grammar reference (a la `dot-spec.adoc`) extracted from the D2 docs.

=== Decisions / Open questions
* D2 has nested braces and is closer to JSON than to flat line-based formats; the parser is the most complex of the three. Plan for an explicit tokenizer (similar in spirit to `DotLines2CjDocument`).
* Roundtripping arbitrary D2 style props is best-effort; preserve unknown attributes verbatim as flat data props.
* Shape/style data is preserved on a roundtrip only when expressible as standard CJ data.

== 3. `reader-ddot`

=== Source material
Code reference: `/Users/maxvolkel/_data_/_git/GitHub/ddot.it-java/src/main/java/com/calpano/ddot/it/reader/basic/DdotItBaseReader.java`
(a 30-line triple parser; ours will extend it with comments, blank lines, continuation, and `ddot.it/on`/`ddot.it/off`).

=== Package & artifact
* artifactId: `reader-ddot`
* package: `com.graphinout.reader.ddot`
* `FORMAT_ID = "ddot"`, extensions: `.ddot`, `.ddot.txt`

=== Grammar (v1)

----
file        := line ('\n' line)*
line        := triple | continuation | comment | blank | switch
triple      := subject ' .. ' predicate ' .. ' object
continuation:= '.. ' predicate ' .. ' object       # inherits subject from preceding triple
comment     := '#' .*
blank       := /^\s*$/
switch      := 'ddot.it/off' | 'ddot.it/on'        # toggles emission
----

Each triple becomes:

* A node for `subject` (if new).
* A node for `object` (if new).
* An edge `subject -> object` labelled with `predicate`, stored as edge data `predicate`.

Predicates with a known set of meanings (e.g. `is-a`, `part-of`, `label`) can be promoted to typed CJ attributes in a future iteration; v1 keeps them as data props.

=== Decisions / Open questions
* Triple separator literal: ` .. ` (space-dot-dot-space) — match upstream `DdotItBaseReader`. We will *also* be tolerant on read (`\\s*\\.\\.\\s*`) but strict on write.
* Should we re-use upstream code as a Maven dep? NO. The upstream `ddot.it-java` is not in the same group/repo and depends on a different `graphinout-version`. v1 plan: **port the 30-line parser** (Yes, but remove copyright stuff, I wrote that parse anyway). Revisit later if the upstream stabilizes.
* The CJ → DDot writer chooses one canonical predicate (`label` or first edge data property) for each edge.
* Full handling of all syntax, including ,, multi-line, is required.

== Test strategy (all three)

. **Service-loader smoke test** — adapt the implicit test from `reader-tgf` that exercises the SPI.
. **Unit reader tests** — mock `ICjStream`, feed an inline string, assert interaction counts (`createNodeChunk`, `node`, `edge`, `documentStart`, `graphEnd`, ...). Pattern copied from `TgfReaderTest`.
. **Resource sweep** — `@ParameterizedTest` over every `*.mmd` / `*.d2` / `*.ddot` resource under `text/<id>/`. Must complete without `ContentError`s above `Warn`.
. **Roundtrip CJ→format→CJ** — copy `TgfRoundtripTest` shape, parameterize over `TestFileProvider.cjResourcesCanonical()`. For Mermaid this exercises the flowchart writer only.
. **Roundtrip format→CJ→format** — normalize whitespace before comparing.
. **CJ-conversion test** — for Mermaid + D2, copy the `DotCjTest` style: parse → emit CJ-JSON → schema-validate.

== Order of work (suggested)

. **reader-ddot** first (smallest grammar, lowest risk, validates the template port).
. **reader-mermaid** next (dispatcher + 8 sub-parsers; flowchart first, then add the others one-by-one).
. **reader-d2** last (requires tokenizer; reuse lessons from the DOT reader).
. After each module: add it to the root `pom.xml` `<modules>` list and run `mvn -pl reader-<id> -am test`.

== Out of scope (v1)

* Mermaid: gantt, journey, pie, requirement, gitgraph, timeline, quadrant, packet, block, kanban, treemap, radar, xychart.
* Mermaid writer for non-flowchart diagram types.
* D2: globs, `@import`, vars, classes (CSS-like reuse), animation hints.
