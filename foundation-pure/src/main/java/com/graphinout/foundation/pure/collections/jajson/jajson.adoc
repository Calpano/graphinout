= Java JSON (JaJson)

The JSON package allows mapping JSON fully to native Java collections and primitive wrapper types.
Life can be simple.

We use the following mapping:

[cols="^,^"]
|===
| JSON | Java

2+h| Primitives
| null | null
| boolean | boolean
| number | Number. Allowed instances must be of type: Integer/int, Long/long, Double/double, BigDecimal (for large numbers) -- see <<Numbers>>
| string | String
2+h| Containers
| array | List<Object>
| object | Map<String,Object>
|===


== Edge cases and behavior notes

The JaJson implementation is intentionally small and predictable. This section documents important edge cases and exact behavior as implemented in `JaJson.java`.

=== Numbers

- Integer numbers are parsed to the smallest practical Java type:
  - Fits into int → `Integer`
  - Else fits into long → `Long`
  - Larger than `Long` → `BigDecimal`
- Fractional numbers (with a decimal point or exponent) are parsed as `Double` if it fits. If a `Double` would be `NaN` or infinite, throw an IllegalArgumentException.
- When serializing Java numbers:
  - `Float`/`Double` values that are `NaN` or infinite are rejected with `IllegalArgumentException` (JSON has no representation for them).
  - All other `Number` values are emitted using their `toString()` form.
- Leading zeros in integers are not accepted (except the single digit `0`).

=== Strings

- Serialization escapes control characters and the usual JSON escapes: `\" \\ \b \f \n \r \t` and `\uXXXX` for other control chars (< 0x20).

NOTE: According to the official JSON specification (RFC 8259), the forward slash (/) is not a character that must be escaped. However, JSON parsers are required to accept \/ as a valid representation of a single / character.

- Parsing supports the same escape sequences, including `\uXXXX`. Java Strings in memory should contain the Unicode codepoint, not an escape sequence.

- The parser is whitespace-tolerant around values but strict inside strings. It allows raw control characters in strings (they will be re-escaped when re-serialized).

=== JSON Arrays and Java Lists

- JSON arrays map to `java.util.List<Object>` when parsing.
- When serializing, `List<?>` are emitted as JSON arrays.
- Multi-dimensional Java lists are serialized as nested JSON arrays.

=== Objects and Maps

- JSON objects parse into `java.util.Map<String,Object>`. Usually preserving key insertion order (e.g. with a `LinkedHashMap`).
- On serialization, any `java.util.Map<String,?>` is supported.
  - A `null` map key throws an exception on serialisation.
- Duplicate keys in parsed JSON will keep the last occurrence (standard `Map.put` behavior) while preserving overall insertion order.
Many JavaScript engines, including V8 (used in Node.js and Chrome), behave this way.

=== Null handling

- `null` is not supported everywhere: only as a value, in arrays, and as object values. But not as object key.

=== Strictness and syntax

{ "foo": "bar", // is optional
  "baz": "bing"
}

- Only JSON whitespace is allowed around tokens: space, tab, CR, LF. Comments are not supported.
- Trailing non-whitespace content after a complete JSON value causes an error.
- Objects require string keys and a colon separator. Arrays and objects must be properly closed; otherwise an error is thrown.

=== Unsupported types

- Attempting to serialize a type outside the supported set (Boolean, Number, String, Character, Enum, arrays, List, Map, or null) results in an `IllegalArgumentException`.

=== Round-trip caveats

- Because map keys are stringified, non-string keys and `null` keys do not round-trip to their original Java key types.
- `Enum` and `Character` values round-trip via JSON strings, not as their original Java types.
