= Graphinout CLI

A command-line interface for Graphinout: read a graph file in one of the supported
input formats and convert it to one of the supported output formats.

All readers and writers are discovered at runtime via the `GioService` `ServiceLoader`,
so the available formats reflect whichever reader modules are on the classpath (the `cli`
module depends on `engine`, which pulls in all readers).

== Build

[source,shell]
----
mvn -pl cli -am clean package
----

This produces a self-contained, runnable jar:

----
cli/target/cli-<version>-cli.jar
----

== Run

[source,shell]
----
# List all supported input and output formats
java -jar cli/target/cli-<version>-cli.jar formats

# Convert, writing to a file
java -jar cli/target/cli-<version>-cli.jar convert graph.gml --to graphml --output graph.graphml.xml

# Convert, writing Connected JSON to stdout (default output format is graphml)
java -jar cli/target/cli-<version>-cli.jar convert graph.tgf --to connected-json

# Inspect a graph: node/edge counts and which model features it uses
java -jar cli/target/cli-<version>-cli.jar analyze graph.graphml.xml

# Which format is this file? Ranked candidates as JSON
java -jar cli/target/cli-<version>-cli.jar detect mystery.txt
----

== `gio` launcher

A `gio` wrapper script lives at `cli/bin/gio`. It locates the shaded jar relative to itself
(building it on first use if missing) and forwards all arguments, so it works from any directory.

Put it on your `PATH`:

[source,shell]
----
ln -s "$(pwd)/cli/bin/gio" /usr/local/bin/gio
# or
export PATH="$PATH:$(pwd)/cli/bin"

gio formats
gio convert graph.gml --to connected-json
----

Pass extra JVM options via `GIO_JAVA_OPTS`, e.g. `GIO_JAVA_OPTS=-Xmx2g gio convert big.graphml.xml`.

== Commands

[cols="1,3"]
|===
| `formats` | List supported input (readers) and output (writers) formats
| `convert <input> [options]` | Convert a graph file to another format
| `analyze <input> [--from <id>]` | Inspect a graph: graph/node/edge counts and the model features it uses
| `detect <input>` | Probe all readers and print the ranked format candidates as JSON
| `version` | Print the version
| `help` | Show usage
|===

=== `convert` options

[cols="1,3"]
|===
| `-t`, `--to <id>` | Output format id (default: `graphml`)
| `-o`, `--output <file>` | Write to a file instead of stdout
| `-f`, `--from <id>` | Force the input format id (default: auto-detect by extension + content probing)
| `-a`, `--anonymize` | Redact labels, types and content before writing (see below)
|===

Parse warnings and progress messages go to `stderr`; the converted graph goes to `stdout`
(or the `--output` file), so piping stdout yields clean output.

=== `--anonymize`

Redacts copyrightable / private material while preserving the graph structure, so a sanitized copy
can be published. Letters become `X`/`x`, digits become `0`, and spacing and punctuation are kept;
node/edge/graph/port ids are remapped to `node1`, `edge1`, … (consistently, so links stay intact);
and JSON keys in `data`/`meta` are remapped to `key1`, `key2`, …

[source,shell]
----
gio convert patient-graph.gml --to connected-json --anonymize
# "Node 1" -> "Xxxx 0";  "Edge from 1 to 2" -> "Xxxx xxxx 0 xx 0"
----

Full details: link:../base/anonymization.adoc[base/anonymization.adoc].

== `analyze`

Inspects a graph file and reports how big it is and which graph-model features it uses. The input is read
into the CJ model first, so `analyze` works for *every* input format (all readers produce CJ), not just
Connected JSON.

[cols="1,3"]
|===
| `-f`, `--from <id>` | Force the input format id (default: auto-detect by extension + content probing)
|===

It prints `key: value` lines to `stdout` (parse warnings go to `stderr`):

[source,shell]
----
gio analyze social/zachary-karate.grale.json
# format:   grale
# graphs:   1
# nodes:    37
# edges:    80
# features: attributes-on-edges, attributes-on-graphs, directed-edges, edge-labels
----

The reported counts (`graphs`/`nodes`/`edges`) are recursive across all nesting levels. The `features` are
the slugs of the model features detected in the document, from the controlled vocabulary defined by the
`com.graphinout.base.cj.analyze.CjFeature` enum (which mirrors the graph-format-registry feature catalog).
The same analysis is available programmatically via `CjAnalyzer.analyze(ICjDocument)`.

== `detect`

Answers "which format is this file?".
Every reader tries to parse the input, and the candidates are ranked by file name and extension, content
kind (XML/JSON/text/binary), format vocabulary and how cleanly each reader parsed the input.
`analyze` and `convert` pick _one_ reader; `detect` shows them _all_.

It takes no options. The result is one line of JSON on `stdout`; pipe it through `jq` to read it:

[source,shell]
----
gio detect mystery.txt | jq -c '{best, tier, top: [.candidates[:3][] | {format, outcome, confidence}]}'
# {"best":"dot","tier":"CONFIDENT","top":[{"format":"dot","outcome":"RECOVERED","confidence":0.850}, ...]}
----

.Top-Level Fields
`best`:: Format id of the highest-ranked candidate.
`tier`:: How sure the result is: `CONFIDENT` (one strong candidate), `AMBIGUOUS` (several close ones) or `UNKNOWN` (nothing recovered).
`contentKind`:: `XML`, `JSON`, `TEXT`, `BINARY` or `UNKNOWN`, determined before any reader runs.
`deepAnalysisSkipped`:: `true` when no reader was run, e.g. for inputs over 1 MB or archives with several graphs. Ranking then rests on file name and content kind alone.
`candidates`:: One entry per reader, best first.

.Candidate Fields
`format`, `label`:: The format id and its name.
`outcome`:: `RECOVERED` (parsed into a real graph), `TRIVIAL` (parsed, but the graph is empty), `ELIMINATED` (parse failed) or `SKIPPED` (not attempted).
`confidence`:: Score from 0 to 1.
`stats`:: Graph, node and edge counts and the model features found, as in `analyze`.
`signals`:: The evidence behind the score, each with a `kind`, `strength` and `reason`.
`errors`:: Content errors the reader reported.
`explanation`:: One-line summary.

The same analysis is available programmatically via `GioInputAnalyzer`, see
link:../doc/usage.adoc#detect[Using GraphInOut as a Java Library].
